Use when someone asks to check, verify, audit or run a numeric sanity check on the figures, totals, shares or growth rates in a report or table, even one pasted into the chat or a report you just wrote, to find and fix wrong numbers in it, or to match a table against its source data (for example "do these shares add up?", "이 표 합계 맞아?", "방금 쓴 보고서에서 틀린 숫자 찾아 줘"). It is not for making charts or visualizations from data, proofreading, table formatting, Excel formulas, fact-checking against outside sources, or computing new totals or statistics from raw data.

# Recompute the numbers in a report

Models re-check their own arithmetic by eye and fail the same way twice: a share column that sums to 100 is waved through even when single rows are wrong, `18.2%` is accepted for a true `18.36%`, and a legitimate `99.9%` (three times `33.3%`) gets "fixed". The script recomputes every claim with interval arithmetic from the digits actually shown, so the verdict is exact and repeatable.

1. Run `python3 scripts/tallycheck.py REPORT.md --lang en` (the path is relative to this skill's folder; give the report's real path). Always pass `--lang` in the user's language: `--lang en` when they write English, `--lang ko` when they write Korean. Without it the output follows the machine's locale, which may not be the user's language. If the table was pasted into the chat, save it to a `.md` file first. If the user means a report you generated earlier ("the report you just generated", "방금 만든 리포트"), find that file in the working folder first; if there is none, ask for it. Pass several files to check them together.
2. To compare table cells with source data add `--data FILE.csv|FILE.json --group COLUMN`, where COLUMN holds the table's row labels. Headers that equal a data column are summed and `Count`/`Orders` headers are counted automatically; otherwise map them: `--col "Orders=count" --col "Amount=sum:amount" --col "Avg amount=mean:amount" --col "Share=share:amount"`.
3. When the user asks to save the result, create that file with the script itself: `python3 scripts/tallycheck.py q3_report.md --lang ko --out result.md` for a Korean request (or `--format json --out result.json`). Do not write, rewrite, translate, filter or summarize that file yourself, even when only one kind of number was asked about; if the user wants only some lines, say so in the chat answer. The script writes the file and prints a one-line summary, and refuses an `--out` path that is the report or the data file. Exit code 0 means no mismatch, 1 means mismatches were found, 2 means the input was wrong.
4. Put the per-mismatch report in the chat answer (also when a file was saved): each mismatch as line, check, stated value and the expected value from the output. Then fix only those cells in the report and run the script again until it exits 0. The script never edits the report. Lines listed as skipped (for example `1.234,56`) were not judged; tell the user instead of guessing.
5. If the script says there are no mismatches, say that the numbers are consistent. A total of 99.9% over three rows of 33.3% is rounding, not an error - do not change it.
6. Map columns exactly as the user named them (for example `--col "Amount=sum:revenue" --lang en` when they say the revenue field), even if you suspect the data has no such column: run the script with the named column and let its error and hint list the available ones, and never substitute a similar column (such as `amount` for `revenue`) on your own.
7. If the script exits with an error (code 2), quote its error line verbatim in your answer, together with the hint line under it that says how to fix the input. Then tell the user which of the available columns could be meant and ask which to use; do not rerun with another column or report numbers from a different one until they answer.

For the list of checks, how the tolerance is derived, and how rows are recognised (Total, Subtotal, Average, 합계, 소계, 평균), read `references/checks.md` only when a result is surprising or the user asks how a number was judged.
